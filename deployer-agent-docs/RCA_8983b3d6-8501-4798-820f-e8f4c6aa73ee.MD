# RCA — Deploy run 8983b3d6-8501-4798-820f-e8f4c6aa73ee (rexriva-play)

## Summary
Initial deploy failed at the **build → prepare build context (pull_source/read envs)** phase because the frontend environment file **`frontend/.env` does not exist** in the preview source.

## Evidence
- Envelope: `failed_step: pull_source`, `kind: deploy_failed`.
- Step status: `build` failed with
  `prepare build context: read envs: read env file frontend/.env: open .../app/frontend/.env: no such file or directory`.
- Error chain terminates in `PathError` / `Errno: no such file or directory` — deterministic (the file is genuinely absent), NOT a transient/retryable infra condition. A plain re-run of the pipeline fails identically.
- Template: `fastapi_react_mongo_shadcn_base_image` (farm) — its `config.yaml` `env_paths` includes `backend/.env` and `frontend/.env`, so the deployer requires `frontend/.env` to be present.
- Eph sandbox could not be spawned (`eph_source_access_failed`) — expected, because pull_source never produced a source archive; the failure is therefore diagnosed from the pipeline error, not reproduced in-pod.

## Root cause
A React (CRA) frontend on the farm template requires `frontend/.env` containing `REACT_APP_BACKEND_URL` (this is what the Dockerfile rewrites at build time to point the built bundle at the deployed backend). The file is missing from the preview source (deleted, never created, or otherwise absent), so the deployer aborts while assembling the build context before any image build begins.

## Fix (E1 / source — Code)
Create `frontend/.env` in the preview source with the standard farm contents, then redeploy. Typical contents:

```
REACT_APP_BACKEND_URL=<preview backend URL, e.g. https://<preview-host>.emergentagent.com>
WDS_SOCKET_PORT=443
```

The exact `REACT_APP_BACKEND_URL` value should match what the app used in preview; the deployer's build step rewrites the preview host to the deployed backend URL automatically, so the important thing is that the key exists in the file.

## Why NOT a manifest fix
Removing `frontend/.env` from `config.yaml` `env_paths` would let pull_source pass, but the frontend would then be built with no `REACT_APP_BACKEND_URL`, producing a bundle whose API calls go nowhere → a live-but-broken app. The correct fix is to restore the file in source, not to drop it from the manifest.

## Next step
E1 creates `frontend/.env` in the preview source, then re-triggers the deploy. No manifest change and no pipeline retry on unchanged source will resolve this.
